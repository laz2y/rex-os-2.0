# REX OS 2.1 — Production Deployment Guide

Deploying REX OS 2.1 to your NAS alongside the existing REX OS 1.0
installation. **Nothing in this guide overwrites REX OS 1.0.**

---

## 1. What the production build is

The production build is the Vite build of the frontend: **`dist/`**
(generated by `bun run build` → `tsc -b && vite build`).

It includes:
- The full REX OS 2.1 UI (all pages, glass theme system, auth flow)
- The six uploaded wallpaper assets:
  - `dist/assets/goku.png`
  - `dist/assets/luffy.png`
  - `dist/assets/naruto.png`
  - `dist/assets/all_three.png`
  - `dist/assets/background.png`
  - `dist/assets/banner.png`
- No credentials — all service tokens/passwords/JWT secret stay
  server-side in `backend/.env` / `backend/.auth-secrets.json`.

## 2. Files to copy to your NAS

Copy **both** the frontend build and the backend into a fresh directory
on the NAS (e.g. `/opt/rexos-2.1/`):

```
dist/                     ← the Vite production build (entire folder)
backend/                  ← the Express API (entire folder)
  ├── server.js
  ├── package.json
  ├── routes/
  ├── controllers/
  ├── services/
  └── smoke.js
```

**Do NOT copy** `backend/.auth-secrets.json` from this workspace — your
NAS should use its own secrets file or environment variables (the backend
already reads `backend/.env` then `backend/.auth-secrets.json`).

Then, on the NAS, from inside `backend/`:

```
npm install --omit=dev     # installs express, axios, bcryptjs, jwt, etc.
```

## 3. Start command

From the NAS, inside the new deploy directory:

```
cd /opt/rexos-2.1/backend
PORT=4000 node server.js
```

That starts one process on **port 4000** that serves BOTH:
- the REX OS UI (`dist/` — served statically with SPA fallback), and
- the `/api` backend (health, auth, system, docker, jellyfin,
  nextcloud, immich, pyLoad).

Recommended: run it under a process manager or systemd so it survives
reboots. Example systemd unit:

```
[Unit]
Description=REX OS 2.1
After=network.target

[Service]
WorkingDirectory=/opt/rexos-2.1/backend
ExecStart=/usr/bin/node server.js
Environment=PORT=4000
Environment=COOKIE_SECURE=true
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

## 4. Required environment variables

All server-side, all in `backend/.env` (or exported in the process env).
**Use your existing NAS credentials — do not generate new ones.**

| Variable | Purpose |
|---|---|
| `PORT` | API/UI port (default 4000) |
| `COOKIE_SECURE` | `true` behind HTTPS so the auth cookie is TLS-only |
| `REX_USERNAME` | Login username (`admin`) |
| `REX_PASSWORD_HASH` | bcrypt hash of the login password (never plaintext) |
| `JWT_SECRET` | Long random string signing session JWTs |
| `PORTAINER_URL` | e.g. `https://portainer.laz2ynas.cc` |
| `PORTAINER_API_TOKEN` | Portainer access token |
| `PORTAINER_ENDPOINT_ID` | Docker endpoint id (3) |
| `JELLYFIN_URL` | e.g. `https://jellyfin.laz2ynas.cc` |
| `JELLYFIN_API_KEY` | Jellyfin API key |
| `NEXTCLOUD_URL` | e.g. `https://cloud.laz2ynas.cc` |
| `NEXTCLOUD_USERNAME` | Nextcloud admin user |
| `NEXTCLOUD_PASSWORD` | Nextcloud app password |
| `IMMICH_URL` | e.g. `https://immich.laz2ynas.cc` |
| `IMMICH_API_KEY` | Immich API key |
| `QBITTORRENT_URL` | e.g. `https://qb.laz2ynas.cc` |
| `QBITTORRENT_USERNAME` | qBittorrent user |
| `QBITTORRENT_PASSWORD` | qBittorrent app password |
| `PYLOAD_URL` | pyLoad web/API base, e.g. `https://pyload.laz2ynas.cc` |
| `PYLOAD_USERNAME` | pyLoad login user |
| `PYLOAD_PASSWORD` | pyLoad login password |

Optional override file: `backend/.auth-secrets.json` — fill-gap values
for the same keys, plus `REX_PASSWORD_HASH` which always overrides.

## 5. Rollback to REX OS 1.0

Because 2.1 lives in its own directory (`/opt/rexos-2.1/`), rollback is
just a service switch:

1. Stop the 2.1 service: `sudo systemctl stop rexos21`
2. Start the existing 1.0 service: `sudo systemctl start rexos1`
   (or whatever your 1.0 process manager was — a simple process swap)
3. Verify 1.0 is serving on its port and `/api/health` responds.

Your REX OS 1.0 files were never touched — the 2.1 install is fully
independent, so rollback is instant and lossless.

## 6. Verification checklist (after starting 2.1)

```
curl http://localhost:4000/api/health        # → 200 {"status":"ok",...}
curl http://localhost:4000/                  # → the REX OS UI (index.html)
curl http://localhost:4000/api/auth/me       # → 401 when logged out
curl http://localhost:4000/assets/goku.png   # → 200 (each of the 6 assets)
curl http://localhost:4000/api/system/connections   # → services status
```
